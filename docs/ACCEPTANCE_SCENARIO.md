# 業務シナリオ受入テスト台本（第1版）

## 目的と判定方法

Windows native 版を owner が operator 役で操作し、日報取込みからバックアップ復元までを 1 セッションで確認する。各 step は、第1層の操作を最後まで実行し、第2層の全項目が期待値どおりなら PASS とする。ひとつでも異なる場合は FAIL とし、後続 step へ進まない。

第1版の在庫反映経路は「入庫記録」+「手動販売出庫」である。Z004 取込みと `pos_stock_sync` 自動在庫連動は対象外であり、この台本の PASS は Z004 経路の受入を意味しない。

## 事前準備

1. 本番 DB と分離した専用受入 DB で Windows native 版を起動する。この DB には実店舗の商品・売上・CSV・バックアップを入れず、開始時点で進行中の棚卸しがない状態にする。次項の受入テスト商品以外の商品は登録しない。
2. 「商品一覧」から「商品登録」を開き、次の専用商品を「登録する」。JANコードは空欄、部門は表示名に「（独自コード可）」が付く任意の部門を選ぶ。「POS販売で在庫を減らす」は「減らさない」にする。

   | 入力欄 | 固定値 |
   |---|---:|
   | 商品名（必須） | 受入テスト商品 |
   | 売価（必須） | 1000 |
   | 原価（必須） | 600 |
   | 数量単位 | 個 |
   | 初期在庫（必須） | 0 |

3. 登録完了メッセージに表示された商品コードを次の欄へ記録し、「在庫照会」で「在庫数」が `0個` であることを確認する。商品は必ずアプリの「商品登録」から用意する。SQL の直接 `INSERT` による seed は在庫と入出庫記録の不一致を作るため禁止する。

   | 項目 | 記録欄 |
   |---|---|
   | 受入テスト商品コード |  |

4. 「在庫少の基準」を開き、「一般商品の基準（必須）」が `3個` であることを確認する。異なる場合は `3` を入力して「保存する」を押し、「在庫少の基準を保存しました」を確認する。
5. 「バックアップ・復元」を開き、「手動バックアップ」の「今すぐバックアップを作成」を押す。「バックアップを作成しました」を確認し、「バックアップ一覧」の先頭行に表示された「日時」を baseline backup として記録する。ファイル名は自動生成され、任意の名前を付ける機能はないため、一覧の作成日時で対象を識別する。ファイル名も補助情報として記録する。

   | backup | 作成タイミング | 一覧の日時 | ファイル名（補助） |
   |---|---|---|---|
   | baseline backup | step 1 の前 |  |  |
   | 機能受入 backup | step 5 の完了後、step 6 の一時入庫前 | step 6 で記録 | step 6 で記録 |

6. 日報 fixture は repository 相対 path `tests/fixtures/daily-report/` の次の 3 file を使う。3 file は synthetic データで、対象日はすべて `2026-03-21` である。

   - `Z001_260321.CSV`
   - `Z002_260321.CSV`
   - `Z005_260321.CSV`

7. 各 step の判定欄に PASS / FAIL と観測値を記録する。FAIL の場合は操作を止め、baseline backup の作成日時に一致する行で「この控えに戻す」→「復元の確認へ進む」→最終確認の「○月○日 ○○:○○ の控えに戻す」を実行し、step 1 からやり直す。入庫・手動販売を個別に取り消して途中から再開しない。

## Step 1 — 日報取込み

### 第1層: 操作手順

1. 「売上データ取込み」を開き、「日報取込み」タブを選ぶ。
2. 「日報ファイルを選択」を押し、`tests/fixtures/daily-report/` の Z001 / Z002 / Z005 の 3 file を同時に選ぶ。
3. 「取込み内容」に表示された「対象日」「総売上」「純売上」「支払集計」「部門別集計」を確認し、「取り込む」を押す。
4. 「日報取込み完了」と「成功」、「在庫数は変わりません」を確認する。
5. 「在庫照会」で受入テスト商品を検索し、詳細の「在庫数」を確認する。

### 第2層: 受入確認観点 + 期待値

| 確認観点 | 期待値 | 観測値 | 判定 |
|---|---|---|---|
| 対象日 | 2026-03-21 |  | PASS / FAIL |
| 総売上 | 12,000円 |  | PASS / FAIL |
| 純売上 | 11,000円 |  | PASS / FAIL |
| 現金 | 11,000円 |  | PASS / FAIL |
| クレジット | 1,000円 |  | PASS / FAIL |
| その他小物 | 3,000円 |  | PASS / FAIL |
| 毛糸 | 8,000円 |  | PASS / FAIL |
| 受入テスト商品の在庫 | 取込み前 `0個` → 取込み後 `0個`（不変） |  | PASS / FAIL |

Step 1 判定: PASS / FAIL

## Step 2 — 在庫反映（入庫 + 手動販売出庫）

### 第1層: 操作手順

1. 「入庫記録」を開く。「入庫内容」の「商品コード・JAN・商品名を入力」で受入テスト商品を検索して「入庫に追加」する。
2. 明細の「数量」を `5`、「原価」を `600` にし、「入庫を保存」を押す。「入庫を保存しました」を確認する。
3. 「手動販売出庫」を開く。「販売内容」の「理由」は「その他」を選ぶ。「商品コード・JAN・商品名を入力」で受入テスト商品を検索して「手動販売に追加」する。
4. 明細の「数量」を `3`、「販売金額」を `3000` にし、「手動販売を保存」を押す。「手動販売を保存しました」を確認する。
5. 「在庫照会」で受入テスト商品を検索して「在庫数」を確認し、「在庫変動履歴」を開く。

### 第2層: 受入確認観点 + 期待値

| 確認観点 | 期待値 | 観測値 | 判定 |
|---|---|---|---|
| 固定数列 | 開始 `0個` → 入庫 `+5個` → 手動販売 `-3個` → 残 `2個` |  | PASS / FAIL |
| 入庫結果 | 「入庫を保存しました」、明細数 1件 |  | PASS / FAIL |
| 手動販売結果 | 「手動販売を保存しました」、明細数 1件、在庫警告 0件 |  | PASS / FAIL |
| 在庫変動履歴 | 「入庫」`+5`・変動後在庫 `5` と「手動販売」`-3`・変動後在庫 `2` |  | PASS / FAIL |
| 在庫少条件 | 現在庫 `2個` は pcs の既定基準 `3個以下` |  | PASS / FAIL |

Step 2 判定: PASS / FAIL

## Step 3 — 在庫少検知

### 第1層: 操作手順

1. 「在庫照会」を開き、状態の「在庫少」を選ぶ。URL は `/stock?status=low_stock` になる。
2. 一覧から受入テスト商品を選び、詳細の「在庫数」を確認する。

### 第2層: 受入確認観点 + 期待値

| 確認観点 | 期待値 | 観測値 | 判定 |
|---|---|---|---|
| 一覧への検知 | 受入テスト商品が「在庫少」で表示される |  | PASS / FAIL |
| 数量と基準 | 在庫 `2個`、pcs の既定基準 `3個以下` |  | PASS / FAIL |
| 在庫切れとの区別 | 在庫 `2個` のため「在庫切れ」ではない |  | PASS / FAIL |

Step 3 判定: PASS / FAIL

## Step 4 — 棚卸し

### 第1層: 操作手順

1. 「棚卸し」を開き、「棚卸しの開始」の「棚卸しを開始する」を押す。
2. 「カウント入力」の「商品コード・JAN・商品名を入力」で受入テスト商品を検索し、「対象を確認」を押す。
3. 表示された「現在在庫」が `2` であることを確認し、「実際の数」に `1` を入力して「数を保存」を押す。
4. 「棚卸しを確定する」を押し、「棚卸しの確定」の「確定すると取り消せません」を確認して「確定する」を押す。
5. 「棚卸し結果」の「差異のあった商品」と「整合性チェック」を確認する。
6. 「在庫照会」から受入テスト商品の「在庫変動履歴」を開く。

### 第2層: 受入確認観点 + 期待値

| 確認観点 | 期待値 | 観測値 | 判定 |
|---|---|---|---|
| 棚卸し入力 | システム在庫 `2`、実際の数 `1`、差異 `+1`（差異 = システム在庫 − 実際の数。正 = システム在庫が多い。35-biz §20.4。在庫を実数へ合わせる補正 movement の `-1` とは符号が逆になる） |  | PASS / FAIL |
| 棚卸し結果 | 受入テスト商品が「差異のあった商品」に表示される |  | PASS / FAIL |
| 棚卸し後在庫 | `1個` |  | PASS / FAIL |
| 在庫変動履歴 | 「棚卸し」`-1`、変動後在庫 `1` |  | PASS / FAIL |
| 棚卸し時の整合性表示 | 「〜件を確認しました。不整合 0件」の文末が `不整合 0件` である（一文の部分引用。先頭の件数は登録商品数に依存） |  | PASS / FAIL |

Step 4 判定: PASS / FAIL

## Step 5 — 整合性検証

### 第1層: 操作手順

1. 「在庫整合性チェック」を開き、「整合性チェック実行」を押す。
2. 完了後の表示を確認する。
3. 「在庫照会」で受入テスト商品の「在庫変動履歴」を開き、在庫と増減を再確認する。

### 第2層: 受入確認観点 + 期待値

| 確認観点 | 期待値 | 観測値 | 判定 |
|---|---|---|---|
| 明示チェック結果 | 「差異はありません」（mismatch_count = 0） |  | PASS / FAIL |
| 対象商品の入出庫合計 | `+5 - 3 - 1 = 1` |  | PASS / FAIL |
| 対象商品の現在庫 | `1個`（入出庫合計と一致） |  | PASS / FAIL |

Step 5 判定: PASS / FAIL

## Step 6 — バックアップ / 復元

### 第1層: 操作手順

1. 「バックアップ・復元」を開き、「手動バックアップ」の「今すぐバックアップを作成」を押す。「バックアップを作成しました」を確認する。
2. 「バックアップ一覧」の先頭行に表示された「日時」を機能受入 backup として事前準備の表へ記録し、ファイル名も補助情報として記録する。baseline backup とは別の作成日時であることを確認する。
3. 「入庫記録」を開き、受入テスト商品を「入庫に追加」して「数量」を `1`、「原価」を `600` にする。「備考」へ `step6復元確認用` と入力し、「入庫を保存」を押す。
4. 「在庫照会」で受入テスト商品の「在庫数」が `2個` になったことを確認する。
5. 「バックアップ・復元」へ戻る。記録した機能受入 backup の「日時」に一致する行で「この控えに戻す」を押す。「復元すると今の記録は戻せません」を読み、「復元の確認へ進む」を押す。
6. 「元に戻せません」の最終確認で、表示された日時が記録した機能受入 backup と一致することを再確認し、「○月○日 ○○:○○ の控えに戻す」を押す。
7. ホームへ戻った後、「在庫照会」で受入テスト商品を確認し、「在庫変動履歴」も開く。
8. 「バックアップ・復元」へ戻り、機能受入 backup より新しい「日時」の控えが一覧に追加されていることを確認する。

### 第2層: 受入確認観点 + 期待値

| 確認観点 | 期待値 | 観測値 | 判定 |
|---|---|---|---|
| backup の識別 | baseline と機能受入 backup の作成日時が別で、復元対象が機能受入 backup の日時と一致 |  | PASS / FAIL |
| 一時入庫後 | 在庫 `1個` → `2個`、備考 `step6復元確認用` の入庫が存在 |  | PASS / FAIL |
| 復元前保全 | 「復元の確認へ進む」の処理により、一覧へ復元直前の新しい控えが 1 件追加される |  | PASS / FAIL |
| 復元後在庫 | step 5 時点の `1個` |  | PASS / FAIL |
| 復元後履歴 | 備考 `step6復元確認用` の入庫 `+1` が消え、入庫 `+5`・手動販売 `-3`・棚卸し `-1` が残る |  | PASS / FAIL |
| 復元完了 | ホームへ戻り、復元後の画面でデータを再取得できる |  | PASS / FAIL |

Step 6 判定: PASS / FAIL

## 終了判定

6 step がすべて PASS の場合だけ総合 PASS とする。FAIL がある場合は、step 名、画面表示、入力値、エラーID（表示された場合）、復元に使った backup の作成日時を実走記録へ添付し、roadmap 項4を完了扱いにしない。
